# Testing Windows features on macOS dev machines

The Windows providers integrate with live OS services (Win32 Event Log and Outlook COM), which cannot execute under Docker (macOS Docker is Linux-only) or Wine (no Event Log service or Outlook COM server), so we adopt a three-tier strategy instead of a single mechanism. Tier 0 keeps the portable parsing/query logic compiled under `#[cfg(any(target_os = "windows", test))]` so it runs in plain `cargo test` on any host; Tier 1 uses cargo-xwin (from the `windows` flake shell, no Docker) to clippy-check the whole workspace, including the Tauri `activity-log-desktop` crate, against the real `x86_64-pc-windows-msvc` target and to cross-build the NSIS installer — we initially tried `cross` (Docker, `x86_64-pc-windows-gnu`), but it could not build the desktop crate and its Wine test runner could not load the Win32 import libs, so it was dropped; Tier 2 commits a VMware Fusion + Packer + Vagrant configuration that builds a Windows 11 ARM box and runs the live collectors from the Mac over SSH with an rsync synced folder. We chose VMware Fusion (free for personal use) and a committed Packer template because no public turnkey Windows-on-ARM Vagrant box exists, and we accept that Outlook COM testing requires a manual, licensed Outlook install inside the VM rather than automated provisioning. A `windows-latest` CI job runs clippy and `cargo test` on every push/PR so Windows-only breakage fails CI instead of slipping past the macOS-only `pnpm verify` gate.
