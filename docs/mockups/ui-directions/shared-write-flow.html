Whichever direction you pick, these pieces are the same: the Access section in each connection's settings, and the prepare, preview, confirm dialog with its outcomes. 1 2 3 4 5
  • 1Access gets its own tab in the connection pane. It stores allow = […] in config.toml, so the CLI follows the same rules. The sidebar row under each source summarises it (“Search, read, create, log time”).
  • 2Write toggles look different (amber when on), and turning on the first one asks once: “Activity Log will be able to create tickets in Work Jira as you.” On a connection with insecure = true they are disabled: “Writes need a valid certificate”.
  • 3What the token can do is shown next to each toggle: allowed (your choice) and granted (the probe) are separate facts. In the UI, an action that is not allowed is hidden, or locked with a link here. An action that is allowed but not granted is disabled and shows this reason.
  • 4Agent rights are a separate, later switch per connection, limited to the actions turned on above. Whether it needs per-project limits is still open.
  • 5Actions history shows actions.jsonl as a table (time, channel, connection, action, target, outcome), next to the Logs pane. It is the human-readable audit for every direction.
